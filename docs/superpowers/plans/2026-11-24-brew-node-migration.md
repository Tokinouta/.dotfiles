# Homebrew Node.js Migration (drop nvm) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace nvm-managed Node.js with Homebrew (linuxbrew) `node`, reinstall all 9 global npm packages under brew's node, repoint every nvm-dependent service to brew, and remove nvm from the dotfiles repo and from `~/.nvm`.

**Architecture:** `brew install node` provides node/npm on `PATH` via the existing `extras/brew.sh`/`brew.fish` chain; npm globals land in `$(brew --prefix)/bin`, which that chain already exports. All consumers (systemd user units, `dsh-web` launcher) get their hardcoded `~/.nvm/versions/node/v26.9.0/...` paths rewritten to `/home/linuxbrew/.linuxbrew/bin/...`. nvm's repo files are deleted and `~/.nvm` is renamed aside as the last step, after every verification passes.

**Tech Stack:** Homebrew linuxbrew (`node` formula, stable 26.13.1), npm 12 (ships with node), systemd user units, bash + fish dotfiles.

**Spec:** none — requirements are the 2026-11-24 user directive ("install node with linuxbrew, migrate all global npm packages there, drop nvm"), captured below. Review decisions confirmed with the user: reinstall at **latest** versions; retire `~/.nvm` by **renaming it aside** (reversible).

## Global Constraints

- Brew prefix is `/home/linuxbrew/.linuxbrew`; every migrated binary must resolve from `/home/linuxbrew/.linuxbrew/bin`.
- Target node is brew's `node` formula (stable **26.13.1** — exact match for nvm's current default).
- Do NOT modify `~/.npmrc` (it carries the npmmirror registry, the `@mi` Artifactory mapping, and the `allow-scripts` allowlist — the migration depends on all three).
- Do NOT edit the DSH-generated shims `~/.local/bin/node`, `~/.local/bin/pnpm`, `~/.local/bin/dsh` ("Do not edit: regenerated by the desktop app"). They are PATH-forwarders and pick up brew's node automatically.
- Do NOT restart `docker.service` (rootless dockerd) — its PATH cleanup is cosmetic and must not disturb running containers.
- Repo commits: Conventional Commits, lowercase, imperative, no trailing period, `Co-Authored-By: Claude Code <noreply@anthropic.com>` trailer. Stage ONLY this migration's files: `CLAUDE.md` carries an unrelated uncommitted `vote` hunk that must stay unstaged; `config/shell/extras/nvm.sh` carries uncommitted lazy→eager edits that are deliberately discarded when the file is deleted.
- This repo has no test suite; verification is command-level with expected output stated in each step.

## Review Focus

- **Fresh-shell `claude` resolution:** today `claude` exists only at `~/.nvm/versions/node/v26.9.0/bin/claude`, which is NOT on new shells' PATH (the alias points at nothing) — a working `claude` from `/home/linuxbrew/.linuxbrew/bin` in both bash and fish is the migration's core success condition (Task 2 verification).
- **Retiring `~/.nvm` under live processes:** three claude sessions currently exec from `~/.nvm/...` and lazy-load from it — the rename must happen only after Tasks 1–4 verify, and the plan expects running sessions may hiccup (Task 5 warning + recovery note).
- **npm install failures:** `@mi/feishu` needs the internal Artifactory registry; `koffi`/`node-pty` build native code — a batch install aborts wholesale on one failure, so the plan isolates failures per package and reports them explicitly (Task 2 fallback loop).
- **Hidden `.nvm` references outside the repo:** 5 files (4 systemd units + `~/.local/bin/dsh-web`) hardcode nvm paths and break silently at login/boot if missed — Task 3 ends with a grep that must come up empty before Task 5 may proceed.
- **Rootless docker disruption:** restarting `docker.service` would stop containers — Task 3 edits its PATH line but explicitly leaves the service running; verification checks it stays active.
